# 智能手表 IPD 流程与 WBS 使用指南

版本：v1.0　资料核验日期：2026-11-08

配套文件：[智能手表_IPD_WBS_可定制模板.xlsx](智能手表_IPD_WBS_可定制模板.xlsx) · [WBS数据CSV](智能手表_IPD_WBS_数据.csv)

## 采用的流程依据

这份模板以公开的 IPD 实践框架为依据，再为智能手表建立工作包、执行计划及评审证据。公开框架、智能手表裁剪建议、示例工期在文件中分别标明。

| 资料 | 用途与引用边界 |
| --- | --- |
| [IBM Research：Concepts in the definition of an enterprise development process](https://research.ibm.com/publications/concepts-in-the-definition-of-an-enterprise-development-process) | IBM 官方研究资料，说明 IPD 覆盖软硬件及服务，重视商业目标、治理和角色；未提供本模板的任务清单或工期。 |
| [华为产品安全基线白皮书](https://www-file.huawei.com/admin/asset/v1/pro/view/44e2e06553364e42b97aca0c9ff333b6.pdf) | PDF 第5页、文内页码05，公开展示六阶段及 Charter、CDCP、PDCP、ADCP、TR、GA，并将安全工作嵌入流程。 |
| [PMI：IBM 开发组织项目管理实践](https://www.pmi.org/learning/library/2019/04/07/15/15/institutionalizing-project-management-development-community-4802) | 1996年原始实践文章，说明跨职能团队、IPMT/PDT及投资检查点。用于理解组织机制，不能直接作为当下公司的制度。 |

主干采用：**概念 → 计划 → 开发 → 验证 → 发布 → 生命周期**。进入概念阶段之前设置 Charter 授权，横向设置需求、质量、成本、供应链、配置、风险及变更管理。

本模板中的工作包、角色名称、工期、准入准出条件，以及 TR 与 EVT/DVT/PVT 的对应关系，是为智能手表编制的建议。正式使用时，由公司确认并发布适用的流程、权限和裁剪规则。

## 六阶段如何落到智能手表

| 阶段 | 需要回答的问题 | 主要交付物 | 本模板评审映射 |
| --- | --- | --- | --- |
| 概念 | 用户是否需要？商业机会和关键技术是否成立？ | VOC、竞品、产品概念、初版PRD、平台/功耗/天线可行性、初版商业计划 | TR1、CDCP |
| 计划 | 做什么产品？投入多少资源？如何验证、生产及交付？ | PRD/SRS、系统架构、堆叠、DVP&R、认证矩阵、WBS、资源及预算、项目承诺 | TR2、TR3、PDCP |
| 开发 | 能否实现完整且可验证的产品包？ | 电子/结构/射频设计、模具、固件、算法、App/云、EVT样机、DVT样机、SIT、产测方案 | TR4、EVT退出、TR5 |
| 验证 | 设计是否满足规格？生产过程与上市条件是否准备好？ | DVT、Beta、认证、PVT、量测/校准、良率/产能、RC回归、服务资料 | DVT退出、PVT退出、TR6、ADCP |
| 发布 | 用户是否能买到、激活、使用并获得承诺服务？ | 受控量产资料、MP首批、质量放行、正式版本、渠道、客服及出货资料 | GA |
| 生命周期 | 在市产品是否持续产生价值并得到支持？ | 质量监控、FRACAS/8D、维护版本、漏洞响应、降本、PCN/EOL/EOS | 上市后复盘、退出决策 |

产品包包括手表、表带、充电配件、App、云端、包装、用户资料和服务能力。具体不适用项应有裁剪记录。

### 三类节点分别管理

- **DCP**：投资与商业决策，建议由 IPMT 或公司授权的同等组织决策。需要判断继续投入、改向、暂停或终止。
- **TR**：技术成熟度与质量评审，由授权技术组织形成结论和放行建议。
- **EVT/DVT/PVT**：样机与制造验证活动及其退出检查。EVT检查工程可行性，DVT检查设计符合性，PVT检查量产过程可重复性；具体范围以批准计划为准。

排期日期、完成率100%、测试报告完成，都不自动代表获批。表内“04评审门禁”单独保存决策、实际签批日期、纪要、条件和关闭期限。

## 从模板建立项目基线

1. 复制文件，用项目代号命名。先确认产品是否为新平台、平台复用还是衍生型号，确定哪些工作包需要保留及复验。
2. 在“01项目配置”输入启动日、状态日期、目标GA和销售市场。默认是中国大陆蓝牙运动健康手表，含App、云和GNSS；其余功能按开关选择。
3. 填写项目及工厂日历，包括节假日、停工和补班。默认尚未录入法定节假日。
4. 各领域负责人确认工作包范围、R/A、交付物、验收标准、工期、依赖、投入和设备窗口。默认FTE为占位，不是实际人员承诺。
5. 逐项完成认证适用性、关键风险和需求验证策划，检查哪些外部合作方或实验室需要提前预约。
6. 查看“06项目看板”和甘特，处理输入错误、资源冲突及目标日期差异。不要仅为匹配目标日期而压缩工期。
7. 组织TR与DCP，形成公司批准的范围、进度、成本、质量和资源承诺。
8. 批准基线后，在完整、未筛选的WBS中，将T/U列计划日期**复制并选择性粘贴为值**到V/W列，记录版本和批准日期，保留旧版本。

蓝色单元格是可编辑输入，灰色单元格是公式。**任务ID**用于依赖，**WBS编码**用于层级，二者不要混用。

## 如何定制任务与排期

### 功能及市场裁剪

范围码控制默认启用，“裁剪设置”允许逐任务选择“自动”“保留”或“不适用”。支持 GNSS、NFC、LTE/eSIM、Wi-Fi、ECG、医疗用途、中国大陆、欧盟、美国和退市场景。

停用任务会成为0工期的依赖桥，继续传递祖先依赖，避免直接删除任务后断开网络。若整条选配链全部不需要，可以统一停用；对基础任务或评审节点的裁剪，应记录理由及批准人。

启用“其他市场”后，需要新增该市场具体准入任务、法源和验证证据，模板不会凭一个开关生成完整准入方案。

### 依赖与工作日

每行支持4个前置ID，使用FS关系及非负工作日间隔。工期为正的任务完成后，后继从下一工作日开始；0工期节点不会额外占一天。

前置必须位于后继行上方，ID全表唯一。该规则使依赖网络易于检查并防止循环。可以筛选；移动或排序任务时须保持前置先于后继，否则输入校验会提示。

需要更多前置时，可以新增0工期汇总节点，分组汇入。需要SS或FF时，可以拆出可验证的中间交付节点，或者扩展到专业排程工具；本版不直接支持这两种关系。

“最早开始约束”用于预约窗口、到料日期、合作方接口开放或实际退市触发时点，不用于自动倒推日期。目标GA仅用来比较差异。

日历从启动年份的前一年起覆盖约12年。额外工作日优先于额外休息日，同日重复配置会在看板提示。超出覆盖范围时应扩展日历并复核公式。

### 新增、拆分与停用

末尾空白行已有公式。新增任务应补全唯一ID、WBS、阶段、工作流、类型、范围码、裁剪设置、R/A、工期、间隔、完成率、交付物、判据及投入。

如果新增任务要成为已有门禁的前置，在主表内部、对应后继之前插入整行，并从相邻正常行复制公式。插行、删行、扩容或结构排序后，需检查甘特、评审、看板和认证链接。已有任务通常建议停用并保留ID，便于追溯基线及变更。

### 进度与资源

每周更新状态日期、完成率、实际开始/完成、证据及风险。实际日期用于执行记录，不自动修改剩余工期；预测变化由PM修改剩余任务的工期、依赖或约束，并保留基线。

模板按逻辑依赖排期，尚未自动资源排平或计算关键路径。估算人日=工期×FTE，只反映该工作包R的粗估需求，未包含所有协作人员。须结合共享工程师、实验室、治具、样机及工厂窗口人工排平。

## 智能手表使用时要重点确认的边界

- **天线与整机**：金属外观、人体加载、天线净空、GNSS及多无线共存需跨RF、结构、硬件共同验证。
- **健康算法**：PPG光路、遮光、接触压力、肤色、人群与运动伪影需形成设计及独立验证证据；验收方法和样本由批准计划确定。
- **防水与材料**：等级应与承诺使用场景、测试方法、密封公差、声学膜及老化复验一致，不能只填写一个等级。
- **续航与安全**：锁定亮度、采样、连接、定位和使用时长等模型，同时验证异常充电、温升与保护。
- **量产一致性**：认证样机、BOM、天线、固件、算法、App、云、烧录文件和产测配置应关联到实际版本与SN。

### 医疗用途

ECG功能本身不单独决定医疗器械属性，应根据用途、宣称、市场等判断。[FDA 2026年一般健康指导文件](https://www.fda.gov/regulatory-information/search-fda-guidance-documents/general-wellness-policy-low-risk-devices)可支持美国一般健康边界的策划，其他市场需补充当地法源。

MED默认关闭。启用后，必须另建经过批准的注册、临床或性能证据专项计划。模板内两个60工作日仅作排期占位，不能作为审批或临床周期承诺；实际适用许可及证据才是放行条件。

### 认证与合规

“10认证矩阵”是适用性判断和证据管理清单。全部初始结论均为“待确认”，功能开关或任务完成日期不构成合规结论。

- [Bluetooth SIG](https://www.bluetooth.com/develop-with-bluetooth/qualify/)：自有品牌产品应按适用主体完成资格流程，不能将供应商设计记录直接当作全部产品资格。
- 中国无线电及CCC：根据具体频段、功率、产品类别、目录和配置确认，参考工作簿中的MIIT及CNCA来源，避免一概认定蓝牙豁免或整机必需CCC。
- 欧盟网络安全：按实际投放日期判断RED/CRA衔接。[2026/339](https://eur-lex.europa.eu/eli/reg_del/2026/339/oj/eng/pdf)规定相关授权法规自2027-12-11废止，不应误解为2026年已取消相关要求。
- 锂电运输：核验型号匹配的UN38.3资料、试验摘要、实际运输配置与包装，不将其称为通用安全认证证书。

## 公司正式落地建议

由公司指定流程Owner，明确IPMT/PDT、技术评审、质量与法规的授权关系；确定各门禁的必需输入、准入准出标准、签批和例外处理。PM负责把这些规则转成有责任人、依赖和证据的计划，并持续维护变更和预测。

所有待批准的质量目标、样本量、续航、防水、良率、产能、软件与安全支持期，都应在项目承诺前填写。首销监控和维护任务只是首轮观察窗口，应持续维护至实际支持期结束；退市任务按真实触发日期启用。

建议使用Excel 2019/365或支持所用函数的新版WPS，并开启自动计算。CSV用于移交任务数据，不包含公式和动态联动。Excel验证结果另见配套“验证报告”。
